# The Quiet Gambit: UX and accessibility review of the library expansion

Scope: index.html, css/styles.css, css/library.css, js/app.js, js/views-openings.js, js/views-lesson.js, js/progress.js. I checked the DOM on localhost at 320×640, 375×812, 768×1024, 1000×800, 1200, 1280×800 and 1440×900. I seeded a mixed progress state (completed, in progress, review on both a completed and an unfinished lesson, active path) and restored `qg-progress-v2` to the empty default afterwards. Contrast figures are WCAG 2.x values computed from the tokens.

**What works:** None of the 15 routes overflows horizontally at 320, 768, 1000 or 1440. At 320 the filters, buttons and step track all reach 44px under a coarse pointer. Heading order has no skips on any route. White and Black stay clear throughout: the square side mark plus a text label appears in the nav, segmented control, lesson rows, lesson head, path cards, line cards, gambit groups and both progress tables, and boards are flipped for Black lines. The library filters cover side, category, level, time, opening/gambit (grouped White / Black / Gambits) and status. The filters persist in the URL, the count is a `role=status`, the empty state has a Clear button, and focus returns to Search after clearing. Line pages show "Arises from", transpositions, related openings and gambits, and practice lessons, with an honest fallback when nothing fits. Most token pairs pass contrast: speculative tag text is 6.19:1 on paper, the review ring (accent-board) 9.13:1 on ivory, `.tag-active` 7.73:1, and graphite metadata 5.92:1. The new components use the original tokens, radii and type, so the visual system stays consistent.

## P1: must fix
1. **On phones, the opening map changes something you can't see.** Below 900px, `.map-side` is moved above the tree (`library.css:180`). At 375×812 the board spans y 539–948 and the info panel 964–1224, while the tree starts at y 1385. Tapping a row, for example "1...e6 2.d4 d5" at y≈1536, updates a board and line list that are about 600px off-screen, so the only visible response is the row turning ink. That breaks the map as a touch tool. Fix: in the `.tree-move` click handler (`views-openings.js:183-184`), call `show(n)` and then, when `matchMedia('(max-width: 900px)')` matches, `$('.map-side').scrollIntoView({block:'start', behavior: REDUCED ? 'auto' : 'smooth'})` and move focus to `#map-info`'s first heading (`tabindex=-1`). Also add a "Back to the map" link in the info panel that returns focus to the pressed row. A better fix is to show a compact inline preview under the pressed row on narrow screens, with the move text, a mini board and the "Defined here" links.

## P2: should fix
2. **The map's live region and side panel are too large.** `#map-info` is `aria-live="polite"` (`views-openings.js:150`). Selecting "1.e4" on the White map injects 26 list items, about 1,080 characters, and all of it is read aloud. The sticky `.map-side` is then 1,849px tall in an 800px viewport (`library.css:169`), so sticky positioning stops working and the list sits far below the board. Fix: remove `aria-live` from `#map-info` and announce a short summary through `A.status('1.e4 e6 2.d4 d5: 3 lines continue from here')`. In `show()` (`views-openings.js:162-165`), cap each list at about 6 items and add an "and N more" `<details>`.
3. **On mobile, the map's focus order doesn't match the visual order.** `order:-1` (`library.css:180`) draws the board above the tree, but keyboard and screen-reader users reach it only after every tree button. With Expand all on the White map that's over 100 stops. Fix: render `.map-side` before `.map-tree` in the DOM (`views-openings.js:144-151`) and use `order` for desktop instead. Also add a "Skip to board" link at the top of the tree.
4. **"What to do next, and why" disappears on browse pages.** It shows on home, path detail, category, progress and lesson completion. It's missing on Lessons (`app.js:329`), both repertoire pages (`views-openings.js:64`), Gambits (`views-openings.js:269`) and line pages. On those pages the header chip shows only counts (`app.js:121-122`). Fix: add a one-line `.next-why` strip under `pageHead`, using `A.nextUp()`: "Next: {title}. {why}" with the `A.nextCTA('btn-secondary btn-sm')` button. Or add "Next: title" to the progress chip popover.
5. **Resuming from home drops the path.** `A.nextUp()` returns a resume suggestion without `path` (`app.js:72`), so the CTA links to `#/lesson/x` without `?path=`. The crumbs then show the category, and on completion `nextAfter` follows the category instead of the learner's chosen path (`views-lesson.js:17-27`). Fix: in the resume branch, attach `path: ap` when `ap.steps` contains `last`.
6. **Progress numbers disagree, because review hides completion.** A completed lesson flagged for review has state `review` (`progress.js:40-44`). The progress card says "3 / 133" completed while the legend lists Completed 2 and Review 2 (`app.js:437-443`). In the category and path tables, White Openings shows 1 filled pip next to "2 of 15" (`app.js:59-61`, `450`). Fix: make the legend read "Completed 3 (1 to review)" and "Review 2". For completed+review lessons, give `pipsFor` the filled pip plus the ring, for example a `pip is-completed is-review` style with ink fill and a blue outer ring (`box-shadow: 0 0 0 2px var(--accent-board)`). Use the same pip in `lessonRow` so the row still reads as done.
7. **"Both sides" means two different things.** In Lessons, "Both sides" filters to lessons tagged for both colours (`app.js:335`). In Gambits, the default "Both sides" means "any side" (`views-openings.js:279`). Fix: in the Gambits filter, rename the empty option to "Any side" and the others to "White" and "Black". Keep "Both sides" only for content that serves either colour.
8. **Tap targets are under 44px on the new components** (coarse pointer, 320–375px):
   - tree toggle 32×40 (`library.css:158`)
   - tree move 40px tall (`library.css:164`)
   - chips 36px tall in the tree, line pages and lesson "Related" (`library.css:125`)
   - links in the progress tables, about 19px tall (`library.css:213-216`)
   - "Position in words" summary, 25px (`styles.css:513`)

   Fix: add `.tree-toggle{width:44px;height:44px} .tree-move,.chip{min-height:44px}` to the `@media (pointer: coarse)` block (`styles.css:559`). Make the table's row link fill the cell with `display:block; padding:12px 0`, and give the summary `min-height:44px`.
9. **Nav links wrap from 961 to about 1120px.** At 1000px, "White repertoire" and "Black repertoire" break onto two lines (58px tall), and the 233px progress chip crowds the nav (`styles.css:143-146`). Fix: add `white-space:nowrap` to `.nav a`. In that band, shorten the labels to "White" and "Black" with a visually hidden " repertoire", or hide `.chip-review` there.
10. **The focus ring is low-contrast on the selected segment.** `.segmented a:focus-visible` uses an inset accent outline (`library.css:114`). On the ink-filled current segment that is 2.17:1. Fix: `.segmented a[aria-current="page"]:focus-visible{outline-color:var(--paper)}`, or keep the default 2px outside offset.

## P3: nice to have
11. **The map doesn't say whose move each row is.** White's map is mostly Black replies ("1...e5"). Prefix the rows with the side mark of the player to move, or add a muted "Black replies" label. Give `.tree-count` sr-only text, "26 lines" instead of just "26" (`views-openings.js:136`). The branch lines use `--rule-strong` (1.87:1, `library.css:154`). Use `--control-border` for the tree connectors.
12. **The map has no arrow-key navigation.** Each node costs 2 tab stops. Consider the APG tree pattern (roving tabindex; Up/Down to move, Right/Left to expand and collapse) on `.tree`, with the chips reachable by Tab from the active row.
13. **Two empty states have no Clear button.** The empty states in the opening list and on Gambits (`views-openings.js:111`, `298`) lack the Clear action that Lessons has. Add the same button.
14. **The Lessons "White" filter excludes "Both sides" lessons.** With side=White, 29 of 133 lessons match and no tactics appear. Add "White (include general skills)" or a "Include both-sides lessons" checkbox. Library search also never surfaces the openings themselves. Add a row of matching opening and gambit chips above the results when `q` matches `Q.line` names.
15. **Lesson-row links have very long accessible names.** Each name combines title, summary, side, category, level, minutes and state (`app.js:43-52`). Put `aria-describedby` on the summary and meta and keep the link name to "title, state".
16. **The "Make this my path" toggle changes its label.** It uses `aria-pressed` while switching its text to "This is your path" (`app.js:288`, `301`). Keep one label, "Make this my path", and let `aria-pressed` carry the state.
17. **In forced-colors mode, the state pips all look the same.** Backgrounds and box-shadows are dropped (`styles.css:550-554`), so new, in progress, completed and review become identical squares. Add `forced-color-adjust:none` on `.pip`, or use `border-style` cues: solid, half (`border-left` thick), filled via `background: CanvasText`, and double for review.
18. **Small layout issues:**
    - The Lessons filter grid puts "Status" alone on a second row at 1440 (`library.css:91`). Use a fixed 4+3 layout.
    - The group pills and the "Opening map / List" pills share one style (`library.css:116-119`). Render the view switch as a `.segmented` control so the two read as different controls.
